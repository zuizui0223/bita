## Author-controlled decisions required before archival release

### 1. Repository licence

There is currently no root `LICENSE` file.

Do not infer a licence automatically. The authors must decide how the repository's different materials may be reused, taking into account:

- original project code and scripts;
- manuscript text;
- original figures generated by the project;
- derived/aggregate products based on external literature or deposited datasets;
- any upstream licence obligations attached to reused data or code.

A code licence and a manuscript/data licence do not necessarily need to be identical. The final repository should state the chosen terms clearly rather than silently implying public-domain reuse because the repository is public.

### 2. Final author identity and approvals

Before release/tagging, freeze:

- author order;
- affiliations;
- corresponding author;
- ORCIDs;
- CRediT roles;
- funding and acknowledgements;
- competing-interest statement;
- all-author approval of the exact submitted version.

### 3. Final reference/house style

The scientific 13-reference spine is clean and regression-tested. Apply only the final *Theoretical Ecology*/Springer house-style formatting after the last manuscript wording edit, then rerun the citation/reference tests.

## Automated final-release sequence

Once the author-controlled items above are resolved:

1. update the canonical manuscript and portal metadata with final author/declaration fields;
2. update/add the repository licence statement selected by the authors;
3. run the full PR test/workflow suite;
4. run `Export manuscript figures` from the exact final commit;
5. retain the generated Figures 1-3 EPS files in the release/submission package;
6. record the exact final commit SHA and successful workflow run IDs;
7. tag a release corresponding exactly to the submitted manuscript;
8. archive that release in Zenodo or another DOI-granting repository;
9. insert the archival DOI and immutable release identifier into:
   - `manuscript/MANUSCRIPT_THEORETICAL_ECOLOGY.md`;
   - `submission/COVER_LETTER_THEORETICAL_ECOLOGY.md`;
   - `submission/AUTHOR_AND_PORTAL_METADATA_TEMPLATE.md`;
   - final Data and Code Availability statement;
10. run one final CI/export pass after DOI insertion if that insertion changes committed files;
11. verify the final portal-uploaded manuscript/figures against the archived release.

## What must not happen

- Do not merge a guessed licence just to remove a checklist item.
- Do not mint the archive DOI from a branch that still lacks final author/declaration fields if the archived object is meant to represent the submitted version.
- Do not regenerate or reinterpret the Leal/Sasidharan quantitative results merely for release consistency.
- Do not replace the final Figures 1-3 with manually edited exports that bypass the committed SVG sources and validation workflow.
- Do not describe the archive release as making third-party source material reusable beyond its original licence.

## Current decision

The repository is ready for final author-controlled metadata/licence decisions. Until those are supplied, creating the definitive submission release or archival DOI would freeze an incomplete authorship/legal package and is therefore intentionally deferred.
